# WebGPU backend

Experimental Compatible-tier backend (DESIGN.md 4.4 "Clarified (Milestone 10.1)"),
`--backend webgpu`, built with `CUERVO_WEBGPU`.

- Implementations: wgpu-native v29.0.1.1 on the desktop (prebuilt, static; fetched by
  `cmake/Dependencies.cmake`), Emscripten's emdawnwebgpu port in the browser. Both
  are the standard `webgpu.h`; `#ifdef __EMSCRIPTEN__` covers the differences
  (no `wgpu.h` extras, no blocking waits in a frame).
- Shaders: the `.wgsl` field of `rhi::ShaderSource`, generated by naga from the
  same GLSL 450 (`cmake/Shaders.cmake`). Entry points are `main`. Texture binding N
  is `@group(1) @binding(2N)` (texture) + `@binding(2N + 1)` (sampler); uniform
  blocks keep `@group(0) @binding(N)`. WGSL has no point size: points are 1 px, as
  on every backend (milestone 10.2).
- Surface: wrapped from SDL's native handles (Wayland, X11, Win32) or the web canvas
  (`#canvas`). Non-sRGB BGRA8/RGBA8, configured with `CopySrc` where allowed so
  `capture_frame` works. With no surface (SDL `offscreen` video driver) the device
  renders into an offscreen texture: the parity tests run headless.
- Frames: one command encoder per frame. A full-target `clear()` before any draw
  becomes the next pass's load op; scissored or mid-pass clears draw a triangle.
  `capture_frame` ends the pass, copies, submits and starts a new pass that loads.
  Natively at most two frames queue (`wgpuQueueSubmitForIndex` + `wgpuDevicePoll`).
- Buffers: every buffer has a CPU shadow (WebGPU writes whole words). An update to a
  buffer that a draw of the unsubmitted encoder reads renames it: a fresh (or retired
  and already submitted) GPU buffer, refilled from the shadow. Stream buffers write
  ranges they have not written this submission in place.
- Bindings: per pipeline, two bind group layouts from the shader reflection tables;
  per draw, bind groups cached by their GPU objects (uniforms use dynamic offsets).
  Unbound uniform blocks and textures read a zeroed dummy.
- Waiting (adapter, device, readback) is native only: `wgpuInstanceProcessEvents`
  plus `wgpuDevicePoll`. In the browser the page requests the adapter and device
  before `main` (`web/webgpu_init.js`) and the device takes it with
  `emscripten_webgpu_get_device()`; nothing blocks, so no JSPI, and captures
  complete asynchronously. Without a device from the page `rhi::default_backend()`
  picks GL (WebGL2) instead (milestone 10.3).
- Parity (10.2): every `rhi_parity` scene equals Vulkan's exactly (wgpu-native runs
  on Vulkan here) and matches GL within the Vulkan edge tolerance; `rhi_parity frames`
  checks the two-frame bound (`webgpu::peak_frames_in_flight`).
